## 后续优先级

**P0：Windows Desktop 真机验收。** 确认实际插件目录、当前版本与源文件比对；在真实宿主里检查技能库、环境首次发送、入口状态、归档恢复及更新前后数据完整性。不得将 Windows runner 的 11/11 契约测试等同于图形界面验收。

**P0：完整更新失败恢复。** 本轮升级工具新增旧插件文件快照、哈希比对以及 pnpm 重新安装失败时的插件副本恢复，测试覆盖安装中途修改并丢失 UI 文件的情况。真实 Windows Desktop 的 junction 行为、锁文件占用与跨进程恢复仍需验收；发生部分回退失败时备份不会清除。

**P0/P1：报告对外分享。** 原始报告默认不变；有明确分享意图时才使用初步脱敏与证据省略模式。自动脱敏无法覆盖所有身份、域名、IPv6、自由文本或嵌入图片内容；必须人工复核。

**P1：Node SQLite 兼容说明。** 官方 node:sqlite 始于 Node 22.5，Node 22.13 起无需实验开关；红队 Store 并不真正支持无该模块的 Node 18/20。先显示准确的诊断和实际要求，不擅自安装额外依赖或改变用户用法。

**P1：技能和工具的宿主实际调用。** 将“文件存在、同步成功、预设指向、宿主注册、模型可用”分别验收，不要以一个页面上的“已列出”冒充全部完成。

## Windows 只读验收参考

先下载同一 Release 的 ZIP 与 SHA256SUMS.txt，在 Windows PowerShell 中计算 Get-FileHash -Algorithm SHA256 并与 SHA256SUMS.txt 对照。

完全退出 DSH 后，在已解压的发布包根目录执行：

    .\scripts\update-desktop-fork.ps1 -CheckOnly -DshHome "$env:USERPROFILE\.dsh"

如果真实 DSH_HOME 不同，改为真实路径。-CheckOnly 只验证版本和关键入口文件，不代表实际宿主启动成功。打开 DSH 后在「管理 → 指南」运行“检查实际安装副本”，再验证技能库、入口、归档及恢复。只记录事实，不把未经测试的项标成完成。
